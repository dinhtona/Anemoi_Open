# LeavePolicy Consolidation: Merge MasterDataLeavePolicies into LeavePolicies

**Date:** 2026-06-30
**Status:** Draft

## Problem

Two tables `MasterDataLeavePolicies` and `LeavePolicies` coexist with near-identical purpose but different:
- Entity base types (Entity vs ValueObject)
- Schema (FK LeaveTypeId vs string LeaveTypeCode)
- Concurrency model (xmin vs none)
- Domain behavior (methods vs public setters)
- Consumers (Settings API vs ESS/Accrual API)

This causes functional bugs:
1. ESS submit fails for policies created via Settings API (validates against wrong table)
2. Accrual worker ignores policies created via Settings API
3. Seed data only populates old table, not new tables
4. Frontend types mismatch backend response shape

## Solution: Approach 1 — Keep MasterData.LeavePolicy, Rename Table

### Strategy

Keep `Domain.MasterData.LeavePolicy` (proper Entity<TId> with xmin, FK, domain behavior, CQRS), delete `Domain.Leaves.LeavePolicy` (ValueObject), rename table `MasterDataLeavePolicies` → `LeavePolicies`.

### 2. Infrastructure Layer

**EF Config changes:**

| File | Action |
|------|--------|
| `MasterDataModelMapping.cs` | `builder.ToTable("MasterDataLeavePolicies")` → `builder.ToTable("LeavePolicies")` |
| `LeaveModelMapping.cs` | Remove `Configure(EntityTypeBuilder<LeavePolicy>)` block (~14 lines). Update 4 FK configs to remove `.WithMany(x => x.<collection>)` → `.WithMany()` (new entity has no `List<T>` navigation collections) |
| `HrDbContext.cs` | Line 102: Remove `DbSet<...MasterData.LeavePolicy> MasterDataLeavePolicies`. Line 39: Change `DbSet<...Domain.Leaves.LeavePolicy> LeavePolicies` → `DbSet<...Domain.MasterData.LeavePolicy> LeavePolicies` |

**Migration script** (hand-written, in new EF migration):

```sql
-- 1. Add new columns to existing LeavePolicies table
ALTER TABLE "LeavePolicies"
  ADD COLUMN "LeaveTypeId" uuid,
  ADD COLUMN "ApplicableGradeCode" varchar(64),
  ADD COLUMN "AnnualEntitlement" numeric(9,2) NOT NULL DEFAULT 0,
  ADD COLUMN "xmin" xid;

-- 2. Copy data from MasterDataLeavePolicies (settings-created policies)
INSERT INTO "LeavePolicies"
  SELECT * FROM "MasterDataLeavePolicies"
  ON CONFLICT ("Id") DO NOTHING;

-- 3. Map old rows that only exist in LeavePolicies (seed data)
--    Find LeaveTypeId from LeaveTypes.Code = LeavePolicies.LeaveTypeCode
UPDATE "LeavePolicies" lp
SET
  "LeaveTypeId" = (SELECT "Id" FROM "LeaveTypes" WHERE "Code" = lp."LeaveTypeCode"),
  "AnnualEntitlement" = CASE
    WHEN lp."AnnualMaxDays" > 0 THEN lp."AnnualMaxDays"
    ELSE lp."MonthlyAccrualDays" * 12
  END,
  "ApplicableGradeCode" = ''
WHERE lp."LeaveTypeId" IS NULL;

-- 4. Map old LeavePolicies rows via LeaveTypeCode
UPDATE "LeavePolicies" lp
SET "LeaveTypeId" = lt."Id"
FROM "LeaveTypes" lt
WHERE lt."Code" = lp."LeaveTypeCode" AND lp."LeaveTypeId" IS NULL;

-- 5. Drop old columns
ALTER TABLE "LeavePolicies"
  DROP COLUMN "LeaveTypeCode",
  DROP COLUMN "MonthlyAccrualDays",
  DROP COLUMN "AnnualMaxDays",
  DROP COLUMN "AllowCarryForward",
  DROP COLUMN "MaxCarryForwardDays";

-- 6. Make LeaveTypeId NOT NULL after data migration
ALTER TABLE "LeavePolicies" ALTER COLUMN "LeaveTypeId" SET NOT NULL;

-- 7. Drop old table
DROP TABLE "MasterDataLeavePolicies";

-- 8. Add FK, indexes, xmin (generated by EF migration tooling)
ALTER TABLE "LeavePolicies"
  ADD CONSTRAINT "FK_LeavePolicies_LeaveTypes_LeaveTypeId"
    FOREIGN KEY ("LeaveTypeId") REFERENCES "LeaveTypes"("Id") ON DELETE RESTRICT;

CREATE UNIQUE INDEX "IX_LeavePolicies_Code" ON "LeavePolicies"("Code");
CREATE UNIQUE INDEX "IX_LeavePolicies_LeaveTypeId_ApplicableGradeCode"
  ON "LeavePolicies"("LeaveTypeId", "ApplicableGradeCode");
```
