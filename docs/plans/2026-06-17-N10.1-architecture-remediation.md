# N10.1 — Notification Architecture Remediation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Fix 6 identified architecture violations in Notification module before N11 — domain encapsulation, ID typing, GUID strategy, aggregate root pattern, HR consumer routing, and string constant centralization.

**Architecture:** Notification follows same Clean Architecture pattern as HR. Entities must encapsulate state behind domain methods. Strongly typed IDs use existing pattern from `Anemoi.Contract.Notification.ModelIds`. MassTransit contracts use centralized constants. The HR consumer uses a strategy/registry pattern for extensibility.

**Tech Stack:** .NET 10, EF Core, MassTransit, Mapperly, FluentValidation, PostgreSQL

- [ ] **Step 7: Simplify consumer**

```csharp
// NotificationActionCommandConsumer.cs — simplified
public sealed class NotificationActionCommandConsumer(
    INotificationActionHandlerRegistry registry,
    ILogger logger) : IConsumer<NotificationActionCommand>
{
    public async Task Consume(ConsumeContext<NotificationActionCommand> context)
    {
        var cmd = context.Message;
        try
        {
            var handler = registry.GetHandler(cmd.TargetService);
            if (handler == null)
            {
                await context.RespondAsync(
                    new NotificationActionResult(false, $"Unknown service: {cmd.TargetService}"));
                return;
            }

            var result = await handler.HandleAsync(cmd);
            await context.RespondAsync(result);
        }
        catch (Exception ex)
        {
            logger.Error(ex, "Error handling notification action for {TargetService}/{ActionCode}",
                cmd.TargetService, cmd.ActionCode);
            await context.RespondAsync(new NotificationActionResult(false, "Internal error"));
        }
    }
}
```
